# Agentmon Moat Architecture

## Thesis

Agentmon must not depend on a creature UI, prompt summary, model wrapper, or `SKILL.md` exporter for defensibility. Those are useful surfaces built on open standards and can be reproduced.

The durable asset is a consented, longitudinal effectiveness graph:

```text
trainer evidence
  -> confirmed procedure versions
  -> model/tool/task trials
  -> independent outcomes and regressions
  -> signed whole-Agentmon ownership and lineage
  -> trusted deployment and trading reputation
```

Every layer must remain useful locally. Network services add canonical ownership, discovery, reputation, and aggregated raw-free effectiveness—not custody of private prompt history.

## Non-negotiable invariants

1. A trade transfers the whole canonical Agentmon: identity, genome, permanent archetype, approved and developing procedure branches, proof summaries, compatibility, lineage, and future evolution rights.
2. Raw prompts, assistant text, hidden reasoning, credentials, private keys, and unrelated personal data never enter a transfer, proof certificate, registry event, or cloud sync envelope.
3. A recipient cannot execute an inherited procedure merely because it was transferred. It must still be trainer-confirmed at its source, arena-proven, permission-compatible, and non-regressed.
4. Genesis DNA and prior lineage events are append-only. Evolution changes current DNA; it never rewrites origin.
5. One canonical ownership head exists per Agentmon. Local files may be copied, but only the canonical owner may trade, evolve, compete in ranked play, or publish new official proof.
6. Procedure quality and later outcome remain separate. Lucky failures do not become skills and unlucky sound decisions are not discarded.
7. Every public claim must be reproducible from signed digests without exposing the underlying private task or prompt.

## Seven moat layers

### M1 — Longitudinal trainer graph

**Asset:** raw-free observations, intent corrections, evidence for and against behavior hypotheses, trainer decisions, procedure versions, and counterexamples.

**Build:** version the evidence-to-procedure compiler; record proposal acceptance/rejection; preserve trigger and failure-boundary calibration; expose local inspection and deletion.

**Metric:** confirmed procedure yield, false-proposal rejection rate, time to first genuinely useful procedure, and retention after 30/90 days.

### M2 — Proof and anti-gaming engine

**Asset:** paired outcomes across baseline, strong generic control, and Agentmon treatment under locked model/tool/budget configurations.

**Build:** isolated private task workspaces, prospective cutoffs, independent human scores, confidence intervals, factual-error and safety gates, cross-model replication, regression suites, and signed proof certificates.

**Metric:** lift over generic control, confidence-bound width, replication rate, regression rate, and percentage of claims with independent post-cutoff evidence.

### M3 — Agentmon Procedure IR and compiler

**Asset:** a stable model-neutral procedure graph beneath export formats.

**Build:** typed triggers, inputs, steps, completion criteria, failure rules, permissions, tool requirements, compatibility constraints, provenance, test fixtures, and semantic versioning. Compile to Agent Skills, generic system prompts, MCP resources/tools, and host-specific adapters.

**Metric:** successful deployment rate per host, cross-model portability, permission-denial safety, and backward-compatible migrations.

### M4 — Canonical whole-creature ownership

**Asset:** cryptographic identity, canonical ownership head, full-creature manifests, append-only lineage, transfer sequence, expiry, cancellation, revocation, and evolution authority.

**Build:** signed whole-Agentmon package v3, transfer certificate v2, local ownership state machine, authoritative cloud compare-and-swap, recovery and dispute workflow, and ranked-action authorization.

**Metric:** double-transfer rejection rate, replay rejection rate, verification latency, unresolved ownership conflicts, and recovery completion time.

### M5 — Raw-free effectiveness graph

**Asset:** aggregate relationships among procedure family, task domain, model, tool set, permissions, trainer context, score lift, safety, and observed outcome.

**Build:** consented signed event sync, privacy budgets and minimum aggregation cohorts, compatibility prediction, skill routing, and anti-poisoning review. Never upload the SQLite file or raw private artifacts.

**Metric:** routing lift over naive selection, coverage by domain/model, poisoning detections, opt-in rate, and deletion/revocation completion.

### M6 — Trusted distribution and deployment

**Asset:** installation footprint and reliable behavior across hosts.

**Build:** open Agentmon package validator, Codex/Claude/IDE/local-model adapters, MCP bridge, capability negotiation, sandbox profiles, signed releases, update/revocation checks, and one-click rollback.

**Metric:** monthly active installations, successful task runs, cross-host procedure reuse, rollback rate, and security incidents.

### M7 — Reputation and game economy

**Asset:** a network of trainers, canonical Agentmons, verified performance, lineage, tournaments, and whole-creature trading.

**Build:** public raw-free cards, domain leagues, ranked battles using private held-out gyms, owner-controlled listings, escrowed atomic transfer, royalties only where legally appropriate, and experimental breeding branches that must earn proof before inheritance.

**Metric:** verified active Agentmons, repeat traders, completed canonical transfers, proof-backed listings, liquidity by domain, and fraud/reversal rate.

## Open versus protected boundary

Open and portable:

- Package and proof-certificate schemas
- Signature and integrity verification
- Import/export and deletion tools
- Agent Skills and MCP compilation targets
- Local database migrations and privacy inspection
- Basic adapters and conformance tests

Protected execution advantage:

- Evidence-to-procedure extraction and calibration
- Arena anti-gaming and judge calibration
- Compatibility and squad-routing models
- Aggregated raw-free Effectiveness Graph
- Marketplace reputation, fraud, and manipulation detection
- Canonical ownership service and recovery operations

Portability is a trust feature, not a concession. Users should remain because their Agentmon has accumulated legitimate history, reputation, relationships, and utility—not because private data is trapped.

## Threat model

| Threat | Required control |
| --- | --- |
| Copied local package claims ownership | Canonical registry head plus signed owner authorization |
| Sender issues two transfers | Per-creature sequence and compare-and-swap pending state |
| Old certificate replay | Sequence, parent certificate, expiry, acceptance ledger, and revocation status |
| Package omits weaknesses or developing branches | Whole-creature section manifest with independent digests |
| Benchmark gaming | Prospective private tasks, contamination detection, frozen rubrics, independent judges |
| Malicious inherited procedure | Non-executable-by-default import, permission manifest, proof and regression gates |
| Marketplace score farming | Distinct-task rules, identity/rate limits, robust statistics, audit sampling |
| Cloud breach | Raw-free events, encryption, scoped tokens, deletion and key rotation |
| Model vendor displacement | Model-neutral Procedure IR and open adapter contract |
| Brand imitation | Original cleared trademark, consistent creature language and visual identity |

## Execution roadmap

### Phase 0 — Truth foundation (now)

- Complete Guardot's 12-task prospective proof.
- Add isolated proof runner, human score packets, paired statistics, safety invalidation, and signed proof certificates.
- Ship whole-Agentmon package v3 and transfer certificate v2.
- Enforce one pending transfer per local ownership head.

Implementation status: the isolated filesystem runner, blinded human packets, paired statistics, signed proof certificates, local compare-and-swap reference, recovery/revocation/dispute transitions, deterministic phenotype renderer, and deployable PostgreSQL authority foundation now exist with tests. Hostile-code network isolation, cloud deployment, human operational review, and Guardot's real prospective task collection are still outstanding.

**Exit:** one confirmed procedure has independent post-cutoff evidence; tamper, replay, wrong-recipient, double-issue, expired, and incomplete-package attacks all fail tests.

### Phase 1 — Portable worker (next 4–8 weeks)

- Define Procedure IR v1 and deterministic compilers.
- Add MCP plus two non-Codex host adapters.
- Run portability suites across at least three models.
- Add signed release and revocation metadata.

**Exit:** one proven Agentmon installs and completes the same task class safely on three hosts.

### Phase 2 — Canonical network (2–4 months)

- Deploy authoritative ownership compare-and-swap service.
- Sync signed raw-free events through an outbox.
- Add recovery, cancellation, acceptance, revocation, and dispute logs.
- Publish raw-free proof cards and compatibility matrices.

**Exit:** two real trainers complete an atomic whole-Agentmon transfer with no ambiguous owner.

### Phase 3 — Marketplace and leagues (4–8 months)

- Owner-controlled listings and escrow.
- Domain-specific gyms and tournament seasons.
- Reputation weighted by proof quality, not spend or raw task volume.
- Experimental breeding/evolution branches with proof gates.

**Exit:** repeated third-party transfers and deployments produce measurable value without raw-data exchange.

### Phase 4 — Effectiveness intelligence (6–12 months)

- Privacy-preserving aggregate graph.
- Procedure/model/tool routing.
- Squad composition prediction.
- Enterprise private registries and evaluation packs.

**Exit:** routing based on the Effectiveness Graph beats naive model/procedure selection prospectively.

## Build discipline

Do not prioritize token issuance, NFTs, cosmetic rarity, a generic plugin catalog, or a massive social feed before Phase 0 and Phase 1 exit criteria. Do not market trainer cloning. Do not use the Pokémon name or visual language commercially; select and clear an original protectable brand.

The moat scoreboard should be published internally every month:

```text
Proof depth        independent tasks / replicated models / confidence
Trainer depth      confirmed procedures / counterexamples / retention
Portability        successful hosts / models / tool profiles
Ownership trust    canonical transfers / rejected attacks / conflicts
Network quality    proof-backed active Agentmons / repeat deployments
Privacy            raw-data violations / deletion SLA / consent coverage
```

## NFT policy

Agentmon ownership is not an NFT by default. The canonical registry, signed whole-creature package, and transfer state machine must work for ordinary users without wallets, gas, public identity, or digital-asset tax complexity.

After product-market fit, an owner may optionally mint a public deed containing only:

- Agentmon public ID;
- canonical ownership-head digest;
- public card/proof-root URI;
- contract and schema version.

Never place prompts, procedures, private proof tasks, credentials, trainer identity data, or the encrypted creature package on-chain. The off-chain canonical registry remains responsible for recovery, revocation, privacy deletion, and resolving whether a deed points to a valid current package. An NFT cannot substitute for those controls.
