# Agentmon Desktop

Version 0.17 moves the verified marketplace into Agentmon Home. The native app now pairs a revocable device credential, compares the local state root with the authority head, attests eligible learned state, and creates or cancels verified listings. The hosted site is the account and registry layer; the Chrome extension is an evidence connector and receives only redacted verified/listed status. The current extension is 0.8.0.

Version 0.13 adds the complete-identity downlink. Every Agentmon Mode prompt now carries the permanent archetype and nature, deterministic resonance, trusted derived working patterns, validated capability tendencies, matched proven procedures, complete failure rules, and an honest host-permission boundary. Developing evidence remains non-executable.

The decision vocabulary is **Check · Call · Raise · Stay · Fold · Bluff · All-in**. Bluff is restricted to explicitly authorized games or sandboxes, All-in always requires trainer confirmation, and live website execution remains simulation-only until a site-scoped Operator workflow earns arena proof.

Version 0.9 bundles the verified Chrome extension inside the app. **Get Extension** copies it atomically to a stable Application Support folder, copies that path to the clipboard, opens `chrome://extensions`, and reveals the folder. Chrome still requires the user to enable Developer Mode and choose **Load unpacked**; the app never bypasses Chrome's installation consent.

Version 0.8 replaces the unbound diamond with a pixel vine whose stem, leaves, bud, particles, and glow grow with hatch readiness. The header displays the installed version, and an unloaded project now presents a prominent folder recovery action instead of looking like the trainer lost their Agentmon.

Version 0.7 adds explicit `/agentmon auto <slot>` browser routing. Each submitted prompt is matched transiently to proven, non-regressed procedures and discarded; no draft, response, or raw prompt is stored. `/agentmon helped` and `/agentmon missed` record derived-only feedback without reading or storing the assistant response.

Agentmon Desktop is the native macOS control surface for the raw-free browser companion. The app starts and stops a narrow pairing/ingestion server that reuses the existing Creation Engine; it does not implement a second learning engine or store prompt text.

Build and open it from the project root:

```bash
node plugins/agentmon-codex/desktop-app/build-desktop-app.mjs
open dist/Agentmon.app
```

The app displays the one-time browser pairing code, extension connection state, every enabled LLM site, a raw-free intake ledger, Signal Light/egg/creature lifecycle, permanent Form I–III state, lineage generation, Promptprint confidence, sample count, learned moves, procedures, and arena-tested/proven counts. Its 1–10 Pixel Snap gauge previews the current Agentmon instantly without changing DNA or touching the shared catalog. A separately confirmed advanced action rebuilds the full art pack in a staging area, reports progress, supports cancellation, and commits only after the whole pack succeeds. The app also shows the active browser downlink and warns if the legacy plaintext feed still exists.

The Local Agent Runtime panel auto-detects common loopback OpenAI-compatible runtimes (including Ollama, LM Studio, vLLM, SGLang, LocalAI/llama.cpp, Jan, and Text Generation WebUI) and accepts a custom localhost endpoint. A selected local model can run a one-shot Agentmon-assisted chat entirely over loopback. Agentmon does not persist the prompt or response; the selected runtime's own retention settings remain outside Agentmon's control. Tool-using CLI agents require explicit adapter-specific permission manifests and are not treated as interchangeable chat endpoints.

New Agentmons show a light that brightens until 60% readiness, bind to a species egg, and hatch at 100% into Form I. Prompt training may improve skills and evidence but cannot rewrite form DNA. Form II and Form III require permanent lineage evolution events; legacy Agentmons are grandfathered into Form II.

`EXTENSION CONNECTED` and `<site> · PROMPT CAPTURE ON` are intentionally separate states. The ledger records site names, event counts, and timestamps—not prompt text. Browser prompt retention remains `derived-only` in the daemon.
